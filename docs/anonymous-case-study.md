# 匿名化案例：旧版 x86 程序在 DEP 下的取指异常

## 现象

某旧版 32 位 Windows 图形程序在现代 Windows 中启动后立即退出。Windows Error Reporting 显示：

- 异常代码为 `0xc0000005`；
- 访问类型为执行/取指，而不是普通读写；
- 故障地址位于一个没有执行权限的 PE 节区。

## 诊断方法

1. 先固定复现条件，记录应用、故障模块、异常代码、访问类型和相对地址。
2. 用只读方式解析 PE 节表，确定故障 RVA 属于哪个节区及其 R/W/X 属性。
3. 检查控制流是否进入了未声明为可执行的区域。
4. 用未修改样本与经授权的修复版本做 A/B 对照，分别观察启动存活、事件日志和功能测试。
5. 对串口类程序，使用独立的测试端口对做双向数据验证，不连接生产设备。

## 技术判断

DEP 会阻止处理器从未标记为可执行的内存页取指。若旧程序把运行时代码、跳板或兼容逻辑放在数据/资源节中，而节属性没有执行权限，现代系统可能以取指访问冲突终止进程。

这类现象不能仅凭“程序很旧”下结论。必须把异常访问类型、故障 RVA、节区范围和页权限串成可重复验证的证据链。

## 合规修复路径

对于自有软件或获得书面修改授权的软件，优先从源代码和链接配置层面修复节区布局，再重新签名和回归测试。对于第三方商业软件，应采用厂商支持版本或请求厂商提供补丁。

不建议为了兼容单个旧程序而关闭整机 DEP，也不应公开发布修改后的第三方二进制或产品专用绕过脚本。

## 验证清单

- 原始复现仍可稳定触发同一异常；
- 经授权的修复版本不再产生新的崩溃事件；
- 程序界面和基本操作可用；
- 测试虚拟串口双向传输一致；
- 不修改系统全局缓解策略；
- 不包含生产设备写入操作；
- 发布物中没有第三方二进制、密钥、个人路径或身份信息。
