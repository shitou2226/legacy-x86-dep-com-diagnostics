# 老程序启动后闪退：一份排查记录

这份记录保留排查方法，省略了具体软件名称、文件和本机信息。这里的步骤供排查时参考，不是对所有旧程序都适用的修复办法。

## 当时看到了什么

一个旧版 32 位 Windows 程序启动后马上退出。Windows 错误报告中的异常代码是 `0xc0000005`，访问类型是执行代码，故障地址对应的程序节区没有执行权限标记。

`0xc0000005` 表示访问冲突，读、写或执行都有可能触发这个错误。要继续判断，必须看清是哪一种访问出了问题。

## 怎么继续排查

1. 按相同操作重新启动程序，确认错误能稳定出现，记录出错模块、异常代码、访问类型和故障地址。
2. 查看程序文件的节区表，核对故障的相对地址（RVA）落在哪个节区，以及这个节区是否标记为可执行。本仓库的文件检查脚本可以查看这些范围和权限。
3. 结合运行时信息，确认程序是否真的跳到了没有执行权限的内存区域。文件中的节区标记可以提供线索，但不能单独代表运行时的内存页权限。
4. 如果有合法的修复版本，在相同环境中对比：能否启动、是否还出现同样的错误、基本功能是否可用。
5. 如果是串口类软件，再用隔离的虚拟串口做双向收发测试，检查收到的数据是否与发送内容一致。

## 为什么要关注 DEP

DEP 是 Windows 的数据执行保护。它会阻止程序在没有执行权限的内存页上运行代码。

有些旧程序可能把运行时生成的代码或跳转逻辑放进数据区、资源区。如果对应内存页没有执行权限，程序执行到这里时就可能被终止。这是一种需要核实的原因，不能看到旧程序闪退就直接认定是 DEP。

## 后续怎么处理

自己开发的软件，或获得书面修改授权的软件，可以从源码和链接配置入手，修正代码所在区域的布局，再重新签名并测试。第三方商业软件则优先使用厂商支持的版本，或向厂商请求补丁。

不建议为了一个旧程序关闭整机 DEP，也不要公开分发修改后的第三方程序或针对具体产品的绕过脚本。

修复后，既要检查启动和错误日志，也要操作界面、验证基本功能。串口软件还应完成双向收发测试。测试过程保持系统保护开启，不连接生产设备；公开记录时去掉第三方二进制文件、密钥、个人路径和身份信息。
